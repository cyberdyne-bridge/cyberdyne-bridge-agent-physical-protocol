# Body Self-Check · 身体自检

- **状态**：Draft 0.1（工具可执行，规范待实机验证）
- **项目**：CPNC（临界协议：中枢核）
- **位置**：本文件属于 CBAP 边的**身体层**约定，不属于协议本体
- **参考实现**：`tools/body_selfcheck.py`，测试 `tests/body/test_body_selfcheck.py`

---

## 0. 为什么要单独有这一层

协议一致性（`conformance-v1.md`，129 条）证明的是：**命令发得对、租约不串、错误码对得上**。
它证明不了另一件事：

> **身体还在不在。**

真实踩过的故障是这一类：

```text
帧率正常、内存正常、进程还活着、日志没有 error
—— 但画面是空的，或者鼠标点不到它。
```

指标全绿而功能已死，是身体层最难查的故障。它不违反任何协议条款，所以协议测试永远抓不到。
本规范就为这一类故障定三个可执行探针。

## 1. 三条判定原则

| 原则 | 含义 |
|---|---|
| **fail-closed** | 拿不到证据 = 失败。"没测到"不等于"通过" |
| **降级要看得见** | 身体必须自报 `degraded` 与原因；静默降级判为失败 |
| **可复现** | 固定轮数、固定预热、固定探针动作；同一身体两次结果应一致 |

## 2. 三个探针

### 2.1 `input.liveness` —— 输入区

**问题**：写下去的动作，真的到达了目标表面吗？

```text
发一个可区分（带随机 token）的动作
  → 读回一个可观测的痕迹（状态变化 / 回执 / 渲染差异）
  → 痕迹必须与 token 对应
```

- 失败条件：无变化、变化与 token 无关、只在第一次生效（后续被吞）、`ok=true` 但痕迹为空；
- 抓的是：窗口还在但输入目标没了（"吞鼠标"）、驱动回 `ok` 但没落地。

### 2.2 `resource.growth` —— 资源增长

**问题**：同一动作重复 N 次，身体会不会越长越胖？

```text
预热 1 轮（丢掉首轮分配）→ 连续 N 轮同一动作 → 每轮采样 RSS / 句柄数
判据：max(后段) - min(后段) <= growth_limit_kb
```

- 失败条件：增长超过阈值、单调上升、或采样缺失（拿不到 RSS 也算失败）；
- 抓的是：每帧/每条日志泄漏、临时文件不回收、句柄泄漏。

### 2.3 `render.variance` —— 渲染输出

**问题**：不同的状态，画出来是不是真的不一样？

```text
请求状态 A → 取输出指纹
请求状态 B → 取输出指纹
请求空/异常状态 → 取输出指纹
判据：A ≠ B；且不得全部相同；且指纹非空
```

- 失败条件：两个不同状态输出完全相同（画面卡死/空白）、指纹为空、所有状态同一指纹；
- 抓的是：「帧率正常但画面是空的」这类最贵的故障。

## 3. 报告格式

探针输出**一份 JSON**，字段固定，便于 CI 与人工复核：

```json
{
  "spec": "body-selfcheck/0.1",
  "target": "fake",
  "rounds": 5,
  "generated_at": "2026-11-08T00:00:00+00:00",
  "degraded": false,
  "degraded_reason": null,
  "ok": true,
  "checks": [
    {"id": "input.liveness",   "ok": true,  "detail": {"token": "ab12", "echoed": true}},
    {"id": "resource.growth",  "ok": true,  "detail": {"rss_growth_kb": 24, "limit_kb": 2048}},
    {"id": "render.variance",  "ok": true,  "detail": {"distinct": 3, "samples": 3}}
  ]
}
```

- `ok` = 全部 `checks[].ok` 为真 **且** 未降级；
- 任一探针无法取证时，该项 `ok=false` 且在 `detail` 写明缺什么，不允许省略。

## 4. 身体要实现的最小接口

探针不假设身体是什么（Mineflayer hand、桌宠、机械臂、任意 MCP 设备）。只要提供：

```python
def send(action: str, args: dict) -> dict      # 至少返回 {"ok": bool, ...}
def snapshot() -> dict                          # 至少返回 frame_hash / rss_kb / fds
```

`snapshot()` 缺失的键 = 该项探针失败（fail-closed），不是跳过。

## 5. 与现有层的关系

| 层 | 证明什么 | 在哪 |
|---|---|---|
| 协议 conformance | 命令、租约、错误码、审计对得上 | `spec/conformance-v1.md`（129 条） |
| 设备契约 | 设备声明合规、能力位正确 | `docs/DEVICE-PARITY.md`（P0–P6） |
| **身体自检** | **身体还在、还能动、还没坏透** | 本文件 |

三者互补，不能互相替代：设备契约合规不代表输入可达，协议全绿不代表画面还在。

## 6. 非目标

```text
不做视觉正确性判定（不做图像比对基准，只做"变没变"）
不做性能基准（只判"有没有涨"，不判"快不快"）
不做安全边界（那是 Kernel / policy / estop 的事）
不替代人工验收
```

## 7. 已知限制

- 三个探针都是**必要条件**，不是充分条件：全绿只说明"没有明显的空壳/泄漏/卡死"；
- `render.variance` 只比较指纹差异，**不判断画得对不对**；
- 阈值（`growth_limit_kb`）与轮数是参数，不同身体应各自标定后写进报告；
- 本规范尚无真实身体的实测数据，状态是 **Draft 0.1**。
